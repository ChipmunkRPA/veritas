# SFace native input and graph runtime: passed synthetic probes

Completed 7 November 2026 after all image-comparison model runs finished. The [prospective source-bound protocol](video-v15-sface-native-protocol.md) was published at `1ff51a0104d68cd70769f3d26e2504d8c08e6a39`. All 13 model-free input/geometry tests and all 24 actual synthetic native probes passed. No real face or project video was scored.

The exact reviewed 38,696,353-byte Apache-2.0 ONNX weight was loaded locally using OpenCV CPU and one thread. Every separate alignment crop matched native `FaceRecognizerSF.alignCrop` byte for byte, and every manually assembled RGB float32 NCHW blob matched the native BGR-input/channel-swap API. All feature outputs were finite, nonzero 1×128 vectors; all native repeats were identical. Direct forward of the same pinned graph in the same OpenCV engine matched the native API with **zero** difference on every probe. No tolerance was changed.

These are 24 self-authored random-color images with synthetic five-landmark geometry, not biometric identity or manipulation examples. The explicit input contract matters: no external centering/scaling was added before the native graph, and RGB/BGR conversion occurred once. The OpenCV reference source was pinned independently; that does not prove which source commit compiled the installed wheel. The [runtime fingerprint](evaluation-panels/video-v15-sface-runtime-fingerprint.json) records the actual local packages/binary, and the [full synthetic receipt](evaluation-panels/video-v15-sface-synthetic-runtime.json) records source/crop/blob/feature hashes and transforms without publishing feature vectors.

The guarded parent exited zero with no guard or sampling error. Duration was approximately 1.24 seconds and the sampled descendant-tree RSS lower bound was 283,312,128 bytes. This is not a true peak or production latency benchmark. [Profile receipt](evaluation-panels/video-v15-sface-synthetic-profile.json).

This establishes local input/runtime compatibility using a separate outer transcription and the same neural engine. It does **not** establish face-swap accuracy, lip-sync detection, identity verification, a forensic operating point, calibrated confidence, cross-platform equality or outside human review. The next step is a frozen consumed-source bounded-transition comparison with ordinary pose/lighting/cut controls and known edit boundaries. Whole-clip swaps may have no transition and remain outside that proposed method. Real face features will remain private. No serving model, customer report, payment setting or GCP resource changed.
