# January 2018 Wikipedia copy-edit intake

Use the exact archived Guild of Copy Editors completed-request index at revision `1271487041`. The January 2018 pilot requires both the request and completion dates to fall within January. Use full-article tasks with one recorded editor. Exclude declined, withdrawn, duplicate and section-specific tasks, and exclude all four articles whose revisions were inspected during reconnaissance, including both articles that supplied exact witnesses. Sort by request date and article title and take 12 distinct articles, capped at three per recorded editor. The archived task, editor and dates remain in the private roster. [Pinned Guild archive](https://en.wikipedia.org/w/index.php?title=Wikipedia:WikiProject_Guild_of_Copy_Editors/Requests/Archives/2018&oldid=1271487041)

Query English Wikipedia for the recorded editor's revisions between the request and completion dates, inclusive. Retain a planned disposition if the article or editor revisions are unavailable or the history is incomplete at the fixed 12-revision limit. Prioritize explicit copy-edit summaries and use revision time and ID to break ties. Check at most two candidate pairs per planned article. A separate official metadata response must confirm both revision IDs, the same canonical article, the child’s exact parent ID, the registered expected editor and the date. Filter known bot, revert, undo and rollback evidence before rendering. [MediaWiki revision API](https://www.mediawiki.org/wiki/API:Revisions)

Render each exact revision directly from the official API. The evidence uses an actual lexical replacement, preserved in the source prose on each side, with an 8–16-word target and 12 unchanged words of context on either side. Both windows must fit within a single unquoted paragraph in their respective versions. The intake excludes quote-bearing paragraphs and capitalization, punctuation and numeral-only changes. The private record stores half-open Unicode offsets in both extracted article texts, plus the official responses and prose hashes. A page with a mechanically valid replacement still needs rights and overlap review.

Review the exact source revisions and attribution history for each proposed window. Pre-upgrade historical Wikipedia revisions remain available under CC BY-SA 3.0, which permits commercial use under its terms. Keep attribution and ShareAlike obligations for any distributed material or adaptations. Screen the actual prose for unlicensed imports, quotations and fair-use content, and review the editor and task history for known bots, reversions and ambiguous intent. An unresolved review does not enter the roster. [Wikimedia historical-revision terms](https://meta.wikimedia.org/wiki/Terms_of_use/Creative_Commons_4.0/FAQ/en) · [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/)

The transport allows up to 62 sequential requests with a one-second gap after each request, a `maxlag` limit, no redirects and no automatic retries. Stop on the first transport rejection, API warning or error. Keep all planned-page dispositions, including pages that could not be reached. A stop during a page's pair collection marks that page incomplete and preserves any completed pair observations. The owner-only cache retains successful replies and a private roster without replacing existing files. The report prints aggregate counts only. [MediaWiki API etiquette](https://www.mediawiki.org/wiki/API:Etiquette)

```sh
python3 -B backend/scripts/text_goce_intake_v228.py /private/tmp/veritas-wikipedia-goce-v228
python3 -B backend/scripts/text_goce_intake_v228.py /private/tmp/veritas-wikipedia-goce-v228 --offline
```

After the offline replay passes, optional `--rights` and `--exposure` inputs report rights admissions separately. Each private rights entry identifies the exact `page_id`, `before_revision`, `after_revision` and `window_sha256`. The window hash is SHA-256 of JSON with sorted keys and ASCII escaping using standard Python spacing. For a negative disposition use `rights_unresolved`, `unlicensed`, `imported_or_quoted`, `bot_or_revert`, or `noneditorial`. Approval uses `source_license` equal to `CC-BY-SA-3.0`, the historical-revision FAQ URL linked above as `source_policy`, a private SHA-256 story group as `story_component`, and positive `checks` for `original_licensed_article_prose`, `quoted_or_imported_material_excluded`, `human_editorial_task_supported`, `bot_and_revert_excluded`, and `archived_attribution_retained`. The exposure input is an array of case-folded, whitespace-normalized 12-word SHA-256 hashes from already consumed project sources. Duplicate article, story and fragment lineage is excluded before counting source admissions.
