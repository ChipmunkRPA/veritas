# Commercial model review — 2026-10-31

This review separates the publisher's code grant, checkpoint grant, dependencies, training-source provenance, and admission to the service. An explicit commercial checkpoint grant is sufficient for the registry's commercial class; it is not a warranty that all training recordings/images/text or every intended use have been cleared. A permissive GitHub code license alone is not treated as an independent checkpoint grant.

## GenD dependency distinction

[GenD code](https://github.com/yermandy/GenD/blob/main/LICENSE), [released checkpoint](https://huggingface.co/yermandy/GenD_CLIP_L_14), and [CLIP](https://github.com/openai/CLIP/blob/main/LICENSE) have MIT declarations/grants. GenD's official face-preprocessing workflow uses InsightFace `det_10g`; [InsightFace explicitly restricts its pretrained models to non-commercial research](https://github.com/deepinsight/insightface#license), despite MIT code. The local application uses its existing MIT-licensed YuNet preprocessing instead and does not download that restricted face detector. This substitution does not prove equivalent crops. [FaceForensics++ dataset access terms](https://github.com/ondyari/FaceForensics/blob/master/dataset/README.md) and other training-source terms are distinct from the checkpoint grant.

Local engineering verification is recorded in `backend/data/model-upgrade-review/gend/verification.json`: official 32 pre-cropped examples match the reference preprocessing/forward exactly, CPU/MPS maximum logit difference is about 2.86e-5, and recropping changes two decision-boundary outcomes. Eight of twelve correlated real examples cross the boundary. These samples may overlap training and are not a valid independent false-positive benchmark. The earlier local admission also found negative incremental value. GenD therefore stays disabled by default.

## Pinned audio implementation and evidence

Pins and SHA-256/size commitments are in `backend/app/models.yaml`. Speech gate revision: `066409f3d9db45a30d21dfcbf9147826ffdd7052`; voice checkpoint revision: `29daea8b04acf2d3f11d1d0da6b01c17fc8a1e4b`; encoder configuration revision: `da985ba0987f70aaeb84a80f2851cfac8c697a7b`. The voice checkpoint includes the encoder weights; no second 600M encoder download is required. All loading is local and strict, with `weights_only=True`; no remote code execution is enabled.

The installed Torch 2.13 environment has no matching available TorchAudio wheel. The original BSD-2-Clause [TorchAudio v2.11 filterbank source](https://github.com/pytorch/audio/blob/v2.11.0/src/torchaudio/compliance/kaldi.py) is retained as pure PyTorch; unused MFCC/native imports are removed. No global Torch downgrade was performed. `backend/scripts/verify_audio_upgrade.py` compares the vendored arithmetic and reference forward using the same loaded weights. Silence, deterministic noise and an existing speech fixture have exactly equal preprocessing/filterbank/logits on CPU (maximum difference zero). The noise control yields a high raw voice response but no detected speech; the gate prevents treating that noise as synthetic speech. This is an integration check, not an accuracy estimate or reason to delete the current baseline.

New sound windows retain source/PCM hashes, exact sample and recording-clock intervals, raw-check commitment, top category scores, selected WAV and waveform PNG. They are frozen into `sound_events` with C01… identifiers. Ordinary views, PDFs, JSON and signed asset packages use the same committed values. Categories apply to the entire mixed ten-second window; they neither separate a background stem nor locate an exact edit. Category scores are not AI probabilities. Historical evidence is read without recomputation.

Commercial defaults now have no unknown/non-commercial exception. Local `loc.fused` remains an explicit enablement of an already commercial-class detector, not a bypass for unknown terms. New candidates carry no inherited calibration or threshold error-rate claim. No old model files or historical results were deleted.
