# Distinguishing interpolation from local camera-pattern loss

A small generated replacement can remove a repeatable interpolation
pattern from an otherwise unchanged camera image. Ordinary resampling
can do the same. This study tests whether a local relationship between
neighboring color samples can explain away some of those ordinary
edits before a region is selected.
[Earlier generated edit pilot](image-native-generated-stencil-transfer-2026-11-13.md)

## Frozen test

Keep the previous texture-supported camera-pattern loss and its
operating point. From the interior of the proposed region, calculate
signed second differences separately on the red and blue channels.
For each axis, fit the differences on one pixel phase from two
neighboring differences on the other phase using nonnegative
coefficients. Repeat in both directions. A region is withheld when
both channels on at least one axis have a fit that reduces residual
norm by more than 70%. The earlier six-camera pilot supplied
development evidence for this operating point. The new check uses
only the submitted native RGB samples.

The prospective panel fixes 13 checksum-verified CC0 RAWs from
camera models outside the earlier camera-grid experiments. All
sources use fixed linear 16-bit development without resizing.
A local Apache-2.0 FLUX.2 Klein generator receives a new source
crop and instruction to place a blue ceramic diamond in it.
Its central generated 128 × 128 pixels are composited back into
the source. The two deliveries use either an abrupt edge or a
ten-pixel cosine blend. Source pixels outside the exact footprint
remain unchanged. Positions alternate between grid alignment and
half-cell displacement. The seven ordinary local treatments
include horizontal and diagonal fractional shifts, cubic
interpolation, rotation, blur, an 8-bit-quantized fractional
shift and tone. The panel also includes each untouched source.
[Held CC0 roster](evaluation-panels/image-native-stencil-interpolation-cc0-roster-2026-11-13.json) ·
[Generator licensing](image-flux-klein-assets-v271.md)

A useful region requires at least 0.30 intersection over union
and 0.50 recovery of the exact changed pixels. The new veto
must retain at least 80% of baseline useful regions and at
least seven useful regions per generated delivery type, halve
ordinary highlights, and leave at most one untouched highlight.
The cue has zero AI-confidence weight.

## Held results

| Delivery | Files | Baseline regions | Regions after interpolation veto |
| --- | ---: | ---: | ---: |
| Generated, sharp edge | 13 | 5 useful | 5 useful |
| Generated, feathered edge | 13 | 5 useful | 5 useful |
| Untouched | 13 | 0 | 0 |
| Bilinear, horizontal | 13 | 0 | 0 |
| Bilinear, diagonal | 13 | 7 | 1 |
| Bicubic, diagonal | 13 | 10 | 2 |
| Bilinear rotation | 13 | 7 | 7 |
| Blur | 13 | 1 | 1 |
| 8-bit-quantized bilinear | 13 | 5 | 5 |
| Local tone | 13 | 0 | 0 |

The interpolation cue retained all ten useful generated locations and
reduced ordinary highlights from 30 to 16 across 104 control files.
The result fell short of both the seven-useful-location minimum per
edit type and the limit of 15 ordinary highlights. Before the cutoff,
the baseline proposed a useful box on ten of thirteen generated
deliveries in each edit type. The veto does not improve the coverage of
the baseline proposal. A rotation varies the interpolation weights
across the region, and quantization can erase the signed relationship.
Both remained common confounders in the held test. The veto remains
experimental.

All thirteen generated images visibly added a blue object intersecting
the predeclared region. One object extended outside the region and
was clipped by the fixed composition. Both delivered versions of each
generated edit changed 16,384 pixels and retained the exact RGB
values everywhere else. Native replay reconstructed all 130 cases.
The scalar audit verified the frozen geometry, integer overlaps, veto
arithmetic and admission decision from the [published measurement ledger](evaluation-panels/image-native-stencil-interpolation-measurements-2026-11-13.json). These
results use one generator, one prompt and one native camera workflow.

## Replay

The generator runs locally with Metal. Scoring and native replay use
the same retained generated bytes and run on CPU. The optional
`--overlay` points to an exact, clean copy of the archived
Transformers dependency when the external drive exposes Finder
metadata files. The independent scalar reviewer needs neither
camera data nor any image libraries.

```sh
python3 -B -IS backend/scripts/review_image_native_stencil_interpolation_transfer.py \
  docs/evaluation-panels/image-native-stencil-interpolation-measurements-2026-11-13.json \
  docs/evaluation-panels/image-native-stencil-interpolation-cc0-roster-2026-11-13.json \
  docs/evaluation-panels/image-native-stencil-interpolation-transfer-2026-11-13.json
```
