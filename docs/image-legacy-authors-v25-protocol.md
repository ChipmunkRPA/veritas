# Legacy photo-owner overlap before learning-role assignment

The new397 image pairs have320 attributed-profile/source components, but the
240 previously consumed photo sources still lack a current owner comparison.
This metadata-only audit checks those missing links before assigning any new
training, calibration or confirmation role. It acquires no photograph or model
weight and runs no source-image neural inference.

The complete240-source plan replays every historical photo reference against
the already retained, hash-bound primary COCO metadata archive. It also checks
the old inventory binding and the published637-source graph. These are source
reference checks, not independent camera or photographer authentication.
Its guarded local preparation completes with no resource or sampling failure.

The [freeze](evaluation-panels/image-legacy-authors-v25-freeze.json) commits the
private ordered plan, implementation,11 authored owner-identity tests and
unchanged dependencies before any new provider request. The tests reject wrong
photo/server/secret, owner mismatch, non-photo responses and ambiguous profiles.
They explicitly refuse to infer a commercial photo grant from an owner match.

## Once-only public metadata requests

- Request the public Flickr oEmbed reference once for every planned source, in
  fixed source-ID order. Use a fresh session without account credentials or
  netrc authentication; retain TLS/proxy verification. Follow no redirect.
- Wait at least0.5seconds between starts, use10/20-second timeouts and accept
  at most100000 bytes of metadata. Retain bounded partial/error bodies and
  status records. On HTTP429, make no further requests; keep all remaining
  planned rows explicitly unrequested. Do not retry unavailable cases.
- A matched owner requires the exact historical photo ID, server and secret,
  a provider photo response, canonical HTTPS profile/photo URLs agreeing on
  the owner, and a bounded nonempty public author name. License changes are
  not classified here; matching a profile cannot grant training rights.
- Replay every retained successful body and keep the complete240 denominator.
  Unresolved identities remain unresolved rather than becoming a "fresh" label.

The data-only worker uses the unchanged generic900-second,6-GiB sampled RSS
monitor with1536-MiB RAM/disk reserves. This lightweight metadata phase has
different needs from the separately prepared full neural probe; the latter's
stricter starting-headroom gate is not bypassed. A failed/incomplete metadata
phase remains retained and is not automatically restarted or replaced.

## Result use and limitations

Enrich only the old-source profile fields in the existing private graph, then
recompute the same fixed source/profile/exact-pixel/thumbnail components. Keep
every new and old source record. Report how many new groups become connected
to prior-consumed sources and how many publisher-nontraining candidate groups
remain without a detected link. Do not assign roles or fit a model as a side
effect of this audit.

Provider ownership is an account reference, not proof of an individual creator.
Unknown old owners, aliases, bursts/crops and external pretraining overlap still
limit independence claims. The earlier48-source confirmation minimum remains.
Raw provider identities, photo links, source pairings and thumbnail vectors stay
private; publish aggregates and whole-file commitments only. Outside human
reviewers remain0, no outreach approval is assumed, GCP is deferred and GitHub
workflows stay disabled. Publish reviewed updates by direct push.
