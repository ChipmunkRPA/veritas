# SFace synthetic input and native runtime check

Prospective compatibility test, 7 November 2026. No project video, real face, biometric reference database or face feature is used here. The separately reviewed SFace weight remains a research asset; no consumer detector, confidence or report changes are authorized by this test alone.

The reviewed [OpenCV source](https://github.com/opencv/opencv/blob/40738fb16ceddb5fb3fea747585f7ce6abb0605b/modules/objdetect/src/face_recognize.cpp) resolves the official `5.0.0` tag to commit `40738fb16ceddb5fb3fea747585f7ce6abb0605b`. Its SHA-256 is `92bb8b201f2f84c19e5be93495a0c6069f9b32deb78d7c8c3ba24e53e0b3e53e`. This pins a reference input contract; it does **not** establish the exact source commit used to compile the installed wheel. Actual comparison with the installed native API remains necessary.

That implementation accepts five float32 landmarks in the native 15-value detection row, aligns a 112×112 crop using its stored target coordinates and rounded target mean, and uses bilinear warping. Its `feature` method creates an RGB float32 NCHW blob from a BGR crop with outer scale 1 and mean zero. The graph may perform internal normalization. Do not add an external `[-1,1]` normalization or feed RGB into an API that swaps channels again. The research transcription preserves upstream float/double calculation stages and refuses degenerate landmarks.

Before any project-frame forward, run 24 authored synthetic probes: random-color RGB images of 240×180 pixels using seeds 20261107 through 20261114, and three fixed scale/rotation/translation combinations per image. These are not pictures of people or quality labels. Convert once to BGR and compare the installed native `FaceRecognizerSF.alignCrop` against the separate source transcription, and native `blobFromImage` against the direct channel/transposition implementation.

Fixed requirements: every aligned crop and input-blob byte must match, all features must be finite/nonzero with the same native/direct graph shape, repeated native feature calls must be identical, and a direct forward of the exact same pinned ONNX file in the same OpenCV CPU engine must differ by at most 1e-4 absolute and 1e-5 relative to the maximum native feature magnitude. This is a separate outer-input review using the same inference engine, not an alternate neural implementation. Every failed probe and its hashes is retained; no project-media scoring or silent tolerance adjustment follows a failure.

Run only after the current image comparison's model jobs finish. Use CPU and one OpenCV thread, reviewed weight/source hashes, no package install and no publisher Python execution. The runtime helper refuses to compete with the active image/audio/writing/video study modules. Retain full source-image, crop, blob/feature bindings and operation metadata for synthetic inputs. Publish scalar receipts/hashes only; real face features remain private in later studies.

The `--profile` parent samples the descendant process-tree RSS every 0.1 seconds, stops above 2 GiB or below 1.5 GiB available system memory, and stops after 180 seconds. Retain guard failures, exit codes and sample errors. Sampled memory is a lower bound, not a true peak. A profile run is required; running an unguarded worker alone does not satisfy this protocol.

A successful runtime check permits freezing the consumed-source bounded-transition comparison, using source-clock-verified frames, the same tracked face before/during/after a known edit, and ordinary appearance/pose/lighting/cut controls. It is not face-swap detection accuracy, lip-sync coverage, identity verification, a calibrated probability, a fresh quality study or outside human review. A consistent whole-clip face swap may contain no transition for this method to detect. Publisher identity-match points will not be used as forensic operating points.
