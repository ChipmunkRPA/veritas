# Fresh transfer: serving comparison and achieved-motion review

Prospective design only. This document does not authorize an unfrozen model
stage or report a detector result. The first transfer plan uses the original
source components admitted by the complete v142 replay. Generated media and
geometry require their own published contracts and actual successful receipts.

## Compare the service users receive

The existing correlation diagnostic on injected dense one-face tracks is a
component baseline. Its earlier failures do not establish that a candidate
improves the complete serving pipeline. Before any default change, run the same
constructed clips through the actual current production pipeline, model manager,
registry and tracking code in an isolated local database/object store. Freeze
the relevant application sources, manifest, cached commercial model records,
package versions, nonsecret configuration and existing fusion/calibration assets
before the first response. Do not substitute injected tracks for serving tracks.

Keep three comparisons distinct:

1. Frozen candidate heads versus the existing timing diagnostic on equivalent
   explicitly described inputs, including all unavailable outputs.
2. Current appearance/sequence review and fallback versus candidate inspection
   evidence, including ordinary-edit flags and localization coverage.
3. Current complete service versus the same service with the candidate added.
   Any candidate fusion needs a separately frozen rule and suitable calibration;
   an inspection cue with zero confidence weight is not a calibrated overall
   improvement.

An explicitly requested full-profile CPU benchmark is separate from the default
CPU auto-profile, which can resolve to quick and omit tracking and timing checks.
Record the resolved profile, actual scheduled/completed/skipped checks, resource
failures, sampling support and tracking losses for every case. Compare full with
full and default with default. Never turn a skip, unsupported input or inconclusive
output into an original-file success. Preserve the 900-second/6-GiB model bounds
and all initial/running reserves; unavailable resources are an observed limitation.

Report detections, missed neural edits, ordinary/original false alarms,
unassessed cases, temporal overlap and outside-edit flagged duration, together
with paired gains and losses at the unchanged internal research settings.
Separate a correct timing-discrepancy flag on an ordinary cut/audio delay from a
false assertion that the control was AI-generated. Keep variants from the same
source/content component together; they are correlated observations, not new
independent recordings. No source-quality or response-based replacements or
calibration fitting on transfer sources are allowed.

## Measure generated motion separately from detector scores

Full-expression driving and speech conditioning describe generator inputs.
Neither changed pixels nor a requested 320-ms driver shift proves the output
actually follows the driver's visible articulation. Keep all generated cases,
including static, unstable and untrackable ones, in the evaluation denominator.

A separate predeclared stage should independently track the **native composites**
and genuine source/earlier reference sequences at their observed timestamps.
It must not reuse generator latent motion values as measured output motion.
Use timestamp-normalized lip shape and relative motion, separating tracking
coverage, pose/scale normalization and missing runs from motion evidence. Compare
source-like and driver-like shape distances and complete lag curves; report weak
reference motion and ambiguous/multiple lag peaks as unassessed. Do not choose
a favorable lag, detector setting or source after seeing the curves. Publish
the exact normalization, landmark indices, support requirements and numerical
rules in that stage's frozen contract before execution.

Blind local visual review can separately describe teeth/lip instability,
boundary discontinuities and visible redraw artifacts. It is not outside expert
review or proof of realism. Visible trajectory transfer supports a limited motion
claim; it does not establish achieved phonemes, intelligibility or audio content.
Benchmark media from these constructions are mouth redraws, not identity
face swaps or a representative sample of all commercial generators.

## Adoption requires an actual app flow

After a candidate earns adoption on both useful detections and its false-alarm
cost, verify representative manipulated, original and unassessable cases through
the real local worker and prepaid queue, using only simulated/test-mode Stripe.
No inference may start before paid confirmation. The browser, API, JSON, PDF and
evidence package must agree on time ranges, frames and audio support. Customer
outputs must hide detector model names, explain unsupported checks, retain
separate speech/visual/timing scope and link expert inquiries to
sales@chipmunkrpa.com. Check rollback as part of this integration, without
overwriting historical reports or evaluation failures.

No adoption, confidence change, GitHub Actions, outreach, live payment or GCP
deployment is performed by this design document. Private media, vectors,
per-input fingerprints and learned parameters remain private.
