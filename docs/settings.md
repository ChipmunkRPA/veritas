# Settings

Generated by `backend/scripts/settings_doc.py` from `Settings.model_fields` (`backend/app/core/config.py`); do not edit.
`make settings-doc` writes it again, and `tests/test_settings_doc.py` fails when it is stale or a field has no description.

- **Where a setting is read.** The environment of the process, then `backend/.env` (a directory install). A list or an
  object is given as JSON. A value that is refused stops the start and names the setting, never its value.
- **Docker Compose** gives `api` and `worker` a setting in one of four ways:
  - ○ `docker-compose.yml` fixes the value;
  - ◐ `docker-compose.yml` takes it from the environment of `docker compose` (or the `.env` file beside it) and has
    a default of its own, or requires it. Set it there: it is not read from `veritas.env`;
  - ● it is passed on when it is set in the environment of `docker compose` (or in `.env`); else its line in
    `veritas.env` applies, else the default below (`docker-compose.settings.env` holds these names);
  - no mark: a `NAME=value` line in the optional file `veritas.env` beside `docker-compose.yml`.

  `models-init` reads neither file. Runbook: "Configuration".
- **Defaults** are those of the code; `<backend>` is the directory of the backend. The image sets
  `VERITAS_ENVIRONMENT=prod`, `VERITAS_DATA_DIR=/data` and `VERITAS_MODELS_DIR=/models`.
