# LTX public audio marking: prospective native contract

The official Lightricks marking pack documents opt-in video and audio marks,
including public detection code. This is a real local-verification candidate,
not another provider-private key or a claim to cover every LTX export. Its
code explicitly says the marks are not cryptographic signatures. The source
read-through found two important distinctions: audio `detected` tests family
presence rather than the expected payload, and the returned `payload` is the
baked expected pattern, not recovered bits.

Pin the code at `4f521619ae0029e8fbb64d555030c2b121a33b4f` and marking pack at
`718f58d124e0acf58da85752692d93b0bd54c38a`, with all12 small source/declaration
files and checkpoint identities in the executable source lock. Code is
Apache-2.0; the pack's two Meta component notices grant MIT. LTX generation
weights have separate terms and are not used. The audio generator/detector
match the exact16-bit weights already cached for the public-family study;
verify every source/dependency file and loaded tensor through the existing
restricted loader. Do not call upstream unrestricted pickle or download
entry points, install its full generation package or substitute a random model.

Only execute inspected AST definitions: result type, bit-test arithmetic,
channel layout, baked payload and marker methods, excluding the `create`
loader. A small local Audio value supplies the unchanged waveform/rate fields.
This tests the published marking arithmetic with verified compatible models,
not the complete upstream loader or media pipeline.

## Fixed cases and interpretation

Publish and verify the protocol, source and freeze before native media forwards.
Use four deterministic mathematical stereo carriers, two seconds each, at
native24 and48kHz. They are not human voices or full AI-generation samples.
For each rate/carrier pair score six cases: unmarked; the baked public payload;
its complement; opposite payloads across channels; a mark only in the middle
second; and a matching mark with deterministic5dB noise added. Marking operates
on two separate mono batch items, without downmix or internal resampling.

That gives48 native PCM cases. Add32 file cases: unmarked and matching marks
for all eight pairs, each through PCM16 WAV and128kbps AAC/M4A. Preserve stereo
and the declared native rate; bind actual stream timing, file bytes and the
first exact two decoded source seconds. Lossy codec changes are expected and
retained. This is an audio-only contract; no video PixelSeal model is executed.

Run every planned case, not just strong positives. Repeat the first generator
and detector input bitwise. Expected totals are17 generator and81 detector
forwards. Capture actual channel/sample probabilities and message responses.
Independently reproduce strict per-sample `>0.5`, clip fraction `>=0.5`, actual
decoded bits and the inclusive integer binomial tail for16 bits. The smallest
possible perfect-match p-value is1/65,536, not an AI-authorship probability.

Keep family presence, exact public-pattern recovery and origin authentication
separate. A wrong-payload presence hit must not become LTX attribution; even
an exact public pattern remains copyable post-hoc marking. Neither can skip
statistical detection or supply AI-origin confidence. Absent, failed or
unavailable signals cannot establish originality. Keep model names out of
future customer evidence; this experiment is research only.

## Audit, resources and limits

Retain all80 case records, packets, errors and codec proofs. Review every saved
sample probability, decoded-bit comparison, source PCM hash, timing interval,
aggregate and original model-call counter separately; do not claim native
re-execution from an array replay. PixelSeal, provider-export compatibility,
fresh natural speech/music/background controls and full-app/PDF/JSON integration
remain further work. No customer data, raw human voice, face geometry or learned
private weights are published. No service setting or calibration changes.

Run each heavy phase sequentially with a900-second/6GiB sampled RSS guard and
at least1,536MiB available RAM/disk. Retain sampling/guard failures and never
restart implicitly or amend source/parameters after observing results. This
contract demonstrates local executable capability and response semantics; it
does not establish commercial-service error rates, calibrated authorship,
outside human review, court reliability or a completed lip-sync improvement.
