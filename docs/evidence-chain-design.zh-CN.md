# Chipmunk Verify 多媒体证据链设计

日期：2026 年 10 月 31 日。状态：图片证据链第一版已在本地实现并完成验证；视频、音频、文档和邮件的后续能力仍为开发设计。

产品目标是让用户回答三个问题：哪里值得检查、系统实际测到了什么、这些观察能够支持多强的判断。每条局部发现都应连接到原始图片区域、视频帧、音频片段或原文段落，并提供可以核对的截图、回放或引用。整体 AI 检测分数与局部编辑定位是不同能力，必须分别显示。

## 本次已实现的图片证据链

- Plain 与 Expert 结果页均展示图片证据卡：全图定位框、未经缩放的原图裁剪、可切换诊断叠层、实测数值、相关发现、其他解释及限制。支持跳到原件同一位置。
- 新分析发布时自动生成 `chipmunk.image-evidence/1` 不可变证据记录，绑定原件哈希、原结果哈希、分析版本及每张 PNG 的哈希。既有分析可用 `cd backend && .venv/bin/python -m app.evidence.image_packets <analysis-id>` 补齐；读取接口不会触发生成。
- JSON 导出与网页读取同一证据集。标准、取证与摘要 PDF 冻结并嵌入相同图片、观察和引用；公开删减版保留中性引用但不嵌入原图。旧结果、旧证据及既有报告签名不会被覆盖。
- 本版复用已经记录的压缩误差／噪声候选区域；不把分类归因图当作篡改定位。每张图最多展示两个区域，总计最多六个，并记录省略数量。
- 修正了多个人脸分类时最高分与归因输入不一致的问题。新增诊断图覆盖完整原图边缘；坐标不可靠的旧超大图诊断输出会被拒绝或省略，不会强行拉伸到原件。
- 验证包括原件裁剪逐像素一致、EXIF 转正、超大图边缘、证据访问权限、跨分析隔离、篡改拒绝、报告快照与签名、网页／JSON／PDF 证据哈希一致。

**尚未完成**：经过产品验证的精确编辑定位、原图查看器中的连续透明度控制、匹配纹理／光照的对照区域，以及以下视频、音频、文本和文档证据功能。当前卡片中的异常不构成“AI 编辑过这些像素”的证明。

## 开发前基线与后续缺口

现有 Signal、Exhibit、Finding、原件哈希、运行记录和签名报告可以继续使用，不需要重新搭建整套系统。

| 范围 | 已有实现 | 需要补齐 |
| --- | --- | --- |
| 默认结果页 | 结论、发现、信号引用；Expert 中有证据查看器 | Plain 将主要证据放在 Expert 后面。普通用户需要直接看到截图、原文和片段，而不是先理解信号表 |
| 图片 | 分类归因、压缩误差、噪声图、区域查看器；已有局部定位适配器 | 当前定位适配器默认关闭、未获准进入正式判断；缺少每条发现的原图定位与局部裁剪组合 |
| 视频 | 抽样帧、人物轨迹、时间轴、片段和部分逐帧归因图 | 视频查看器没有接入 heatmap；帧时间字段存在毫秒与流 PTS 混用；缺少对应片段的连续帧证据 |
| 音频 | 窗口分数、可疑时间段、波形、频谱、原件播放 | 缺少片段循环和导出、完整窗口关联、剪辑边界检测；已有分段不能当作精确换声起止点 |
| 文本 | 句子高亮、上下文窗口评分、部分解释 | 高亮一句但评分通常使用三句上下文，再受全文估计和平滑影响；缺少局部发现与真实评分范围的明确关联 |
| PDF 和 DOCX | 提取文本并运行文本检测 | PDF 页码和文字框、DOCX 段落结构在提取后丢失；扫描 PDF 无 OCR；缺少原文截图映射 |

| 报告与导出 | 冻结快照、展品哈希、PDF 签名和公开 JSON 投影 | 尚无跨网页、PDF、JSON 一致的局部证据包；公开 ZIP 仍被禁用 |

## 每条发现的用户体验

默认结果页依次展示整体判断、可检查的发现、检测覆盖和局限。证据直接出现在发现下方；详细参数与审计记录继续保留在展开区域。支持和反对同一判断的观察并列出现。

每条发现包含以下内容：

1. **发现和范围**：例如“R1 区域存在压缩差异”或“这段文字的上下文得到较高的 AI 写作检测分数”。
2. **原始位置**：全图定位框、准确视频时间、音频时间段、文档页码及原文引用。
3. **可核对的证据**：原图裁剪与标注裁剪、连续帧、可播放片段、原文高亮。
4. **实测结果及解释**：具体指标、单位、参考基准、测量分辨率和证据类别。
5. **限制及反证**：压缩、拍摄噪声、正常剪辑、模板写作等其他解释；未分析区域；检查之间的分歧。
6. **查看原件与复核**：跳转同一位置、查看上下文、添加人工备注，并在 PDF／JSON 中保留相同证据编号。

示意卡片的布局为“发现标题 → 原件位置 → 原始裁剪／标注裁剪 → 观察及限制 → 打开原件”。这是界面设计，不预先填入虚构异常或概率。没有局部定位结果时明确显示“只有整体判断，尚不能定位具体区域”。无可疑发现时展示检查覆盖和未发现什么，不强行生成红框。

## 证据含义与结论规则

| 证据类别 | 能够表达什么 | 不应推导什么 |
| --- | --- | --- |
| 原始内容或已验证的来源记录 | 原件中的内容、某个来源声明及其验证状态 | 内容本身一定真实、没有来源记录就等于伪造 |
| 局部编辑定位输出 | 检测器在特定区域或时间范围发现编辑模式 | 自动证明编辑来自 AI，或精确到原始单像素的事实 |
| 压缩、噪声、重复区域等异常 | 可复核的信号差异，适合进一步检查 | 异常必然是恶意篡改或 AI 生成 |
| 分类归因或敏感性图 | 哪些区域影响了分类器的输出 | 这些区域就是修改位置 |
| 文本或语音统计检测 | 指定上下文或窗口与检测目标的相似程度 | 精确作者身份、某个单词一定由 AI 生成 |
| 人工复核意见 | 复核者的判断及其引用依据 | 自动改变原机器记录或消除检测不确定性 |

归因图的原始方法描述就是分类决策的重要区域图，通常是粗粒度的，不是编辑掩膜。参见 [Grad-CAM 原论文](https://arxiv.org/abs/1610.02391)。

发布规则：

- 全图 AI 生成判断可以没有局部篡改区域。整张生成图片并不存在一个必然可找到的“被改过的角落”。
- 当前通用定位代码会取非恒定异常图的最高 5% 生成候选区域。它只能表示相对高值，不能作为阳性判定；真实图片也会有最高 5%。
- 同一输出的热力图、裁剪和数值表是同一条证据的不同展示，不计为三条独立支持。相关检测共享输入或基础方法时也不能简单按票数增强结论。
- 分开表示结论支持程度、定位精度和覆盖率。未校准数值叫“检测分数”，不得显示为“该像素 92% 被修改”。
- 原图上下文可用于比较，但不能命名为“修改前图片”；只有实际取得且来源可核对的前版本才能如此标记。
- 解释优先由结构化测量和模板生成。若以后使用语言模型组织文字，每句事实必须引用已存在的观察；上传文档中的指令不能控制解释器。

## 图片证据

图片卡片提供全图定位、原始局部裁剪、标注叠层和邻近上下文。用户可以关闭叠层、调透明度和放大查看；默认不把鲜红热力图当作结论。

后端保留检测输出的原生网格、测量值及数值精度，另外生成用于浏览的 PNG 和缩略图。每次裁剪保存坐标、裁剪前的源图哈希、EXIF 转正、缩放、补边及颜色转换记录。显示坐标以转正后的原图为统一空间，并保存回原始解码空间的变换。相邻区域比较必须说明纹理、亮度、饱和度等条件是否可比。

局部检测输出分为“检查候选”和“经验证阈值触发的局部发现”。分类归因始终保持独立类型。像素图经过放大显示时注明原生网格与有效分辨率，不声称具备原图单像素精度。面积及阈值使用保存的原始测量值和明确的量化规则重算，不能从着色预览恢复数值。

人脸分类的聚合分数与归因图必须绑定同一个输入。本次已修复多个人脸分数取最大值、归因却取第一个人脸的问题，并记录归因输入范围；旧分析仍保留原记录。另外，将“真正分析过的像素范围”和“质量条件下较可信的区域”分为 coverage mask 与 reliability mask，不能用一个裁剪范围掩膜暗示该范围内的判断可靠。

已有定位适配器可复用，但上线条件应包括商用兼容性、权重及代码固定版本、真实照片误报、普通编辑干扰、现代局部生成编辑的泛化以及本机内存测试。现有记录已经提示它们对不同编辑类型的表现差异很大。应分别覆盖传统拼接／复制与生成式填补，不能假设一个定位器通吃。官方 [局部图像编辑定位实现](https://github.com/scu-zjz/Mesorch) 可作为技术基线，不能替代本产品的验证。

## 视频证据

一条视频发现需要“时间范围 + 场景／人物轨迹 + 代表帧 + 前后连续帧 + 对应检查”。点击发现后播放器定位该范围并支持循环，下面提供关键帧胶片条；点击某一帧显示该帧的原始裁剪和叠层。

区分面部替换、画面局部编辑、整体生成迹象和音画不同步四类观察。人物 A／B 仅是本视频内的匿名轨迹，不推断身份。音画偏移可能来自正常配音或剪辑，只作为独立观察。

所有帧锚点统一记录 `stream_id + pts + time_base`、解码帧编号和帧内容哈希。秒数仅用于展示，不作为跨对象关联键。先修复现有 `frame_pts` 毫秒与流时间单位混用，再接入视频热力图。不能把一帧的热力图贴到相邻帧；插值或轨迹传播必须显示为推算位置。

检测采用粗采样后针对候选片段加密采样的两阶段方式。保存每次采样策略及实际分析的帧列表；时间轴清楚显示未采样区间。稀疏采样没有异常不代表每一帧均已检测。片段边界要给出受采样间隔限制的精度，不能用高精度时间小数掩盖低采样率。

PDF 对每条发现输出原始帧、局部标注和前后帧；JSON 和证据包同时带帧锚点、支持窗口及片段文件哈希。

## 音频证据

一条语音发现应显示原始片段的播放／循环、带上下文的试听、实际评分窗口、分数轨迹和定位精度。波形和频谱帮助用户查看同一段声音，它们本身不代表换声证据。音频编辑连续性、合成语音分类及音画同步是不同检查。

保留原件声道、采样率、解码后 PCM 哈希以及分析用重采样／混音链。锚点记录原始流和分析 PCM 的 sample range，再通过有理数采样率、流起点和已知编码延迟映射回播放器。多声道混成单声道后，不能把输出归因于某一个原声道。

已有约四秒窗口及其平滑分段首先作为粗粒度候选，不把平滑阈值的穿越点称为剪辑边界。后续若需要短语或短时换声定位，应单独增加经过验证的部分伪造定位检测。公开研究也专门为局部伪造语音提供分段标签及定位指标，见 [PartialSpoof](https://github.com/nii-yamagishilab/PartialSpoof)。

语音转写及词语时间对齐是后续增强项：转写用于导航，不能证明声音真实。静音、音乐、噪声、语音门控排除段以及超出处理时长的部分均须显示为未检测或不适用。保存片段时同时导出精确截取和含上下文版本，并记录裁剪／转码方式。

## 文本 文档和邮件证据

文本卡片显示标记段落、完整评分上下文、原始窗口分数以及整体先验调整／平滑的影响。现有一句话高亮对应的通常是三句话窗口，产品应写“该段及上下文出现统计迹象”，而不是宣称标记的每个词都是 AI 写的。调整分数属于派生诊断，不能算作独立支持。

全文分类、局部作者变化、风格异常和来源证据分别展示。常见套话、语法正确或低困惑度不能单独证明作者使用 AI。未知语言、过短邮件、模板内容、翻译和混合作者文本需要明确适用范围；文本检测的泛化和改写敏感性已有基准研究支持这一限制，见 [RAID](https://aclanthology.org/2024.acl-long.674/)。

新增不可变的文本来源映射：

- **纯文本**：原始文件／粘贴文本哈希、提取文本哈希、编码与规范化版本；统一采用 Unicode code point 的半开区间，前端通过显式转换切片，避免 Python 与 JavaScript 在 emoji 后错位。
- **PDF**：每个提取片段保留页码、页旋转和文字四边形；空白合并、连字符拼接允许多对多映射。生成原始页面截图及高亮衍生图；映射失败就只显示引用并说明无法定位。
- **DOCX**：锚定段落、run、表格与单元格。只有冻结一个确定渲染器的 PDF 衍生版本后才能给页码，不能把重排后的页码当成 DOCX 固有属性。
- **扫描文档**：先做本地 OCR，保留文字框、识别置信度、识别文本及页图。OCR 噪声是检测条件；无法可靠识别的区域不作 AI 写作判断。
- **邮件**：第一阶段明确支持粘贴正文；原生文件优先增加 EML 的 MIME part、正文、引用历史、签名和附件关系，MSG 转换另行实现。正文检查与发件来源检查分开。粘贴正文不包含完整邮件头，不能判断发件人；邮件头里的认证文字也不能直接当成可信验证结果。

局部写作检测仍是推断。即使标记准确映射到原文，也只能支持该段被检查过及其检测结果，不能由此确定创作过程。

## 统一数据契约

新增 `chipmunk.evidence-packets/1` 版本化旁路记录，关联已发布的 `analysis_id + revision + original_result_hash`。复用现有 Finding、Signal、Exhibit；数据库已经存在部分 Signal 到 DetectorRun 的关联，新增契约把运行输入及变换串联起来，不再另建重复评分机制。

```text
EvidencePacketSet
  id, version, sha256, schema, analysis_id, revision, original_result_hash
  packets[], artifact_refs[], created_at

EvidencePacket
  id, schema, analysis_id, revision, finding_id
  claim_scope: global | spatial | temporal | text
  evidence_type: localisation | attribution | anomaly | statistical | provenance
  anchors[]: SourceAnchor
  observations[]: Observation
  artifacts[]: EvidenceArtifact
  relations[]: supports | contradicts | context | derived_from
  coverage, resolution, limitations[], review_state
  internal_run_refs[]                 仅内部保留

SourceAnchor
  original_sha256, analysed_input_sha256, transform_chain_ref
  image: coordinate_space_id, bbox/polygon/mask_ref
  video: stream_id, pts, time_base, frame_index, decoded_frame_sha256, region
  audio: stream_id, channels, sample_rate, start_sample, end_sample, pcm_sha256
  text: extracted_text_sha256, start, end, offset_unit, source_map_ref
        page/quads 或 paragraph/run 或 mime_part

Observation
  id, anchor_refs[], signal_refs[], capability_label
  measure, value, unit, score_kind, reference, threshold_ref
  calibration_status, independence_group, applicable_conditions

EvidenceArtifact
  id, role, sha256, media_type, anchor_refs[], parent_artifact_refs[]
  render_spec_hash, renderer_version
  role: original_context | source_crop | annotated_crop | mask | curve | clip | excerpt
```

`SourceAnchor` 是按媒体类型区分的 union，不是允许任意字段混搭的对象。全局判断可以只有全局源引用，不要求伪造局部区域。测量没有可靠参考或校准时字段保持缺省并显示未建立，不填入猜测概率。

变换链记录解码器版本、旋转、裁剪、缩放、补边、重采样、文本规范化及父子哈希；几何采用完整变换矩阵，不依赖当前单一 `scale_to_original`。渲染规范记录阈值、色表、透明度、裁剪上下文及显示精度。公开副本保留必要的测量与位置，内部版本额外保留真实模型、权重、参数和运行记录。

建议增加只读接口：`GET /api/v2/analyses/{id}/evidence-packets` 与 `GET /api/v2/analyses/{id}/evidence-packets/{packet_id}`，沿用现有案例权限和媒体访问机制。网页、报告构建器及 JSON 导出读取同一冻结版本。证据补算走有版本的作业，不在 GET 请求中重新推理。

每个 EvidencePacketSet 都是不可变集合，其 `sha256` 对不含该哈希字段的 canonical 内容及成员 artifact 引用计算，不能对自身递归求哈希。新报告请求冻结明确的集合版本、哈希及文件引用；网页和导出按相同版本读取，不能仅用 analysis revision 隐式选择最新集合。旧报告快照未设置的新字段不参与序列化，保持历史哈希有效。

## 从检测结果生成可检查的发现

处理顺序为：冻结原件 → 记录分析输入及变换 → 保存原始检测输出 → 建立观察和源锚点 → 按位置与假设组织证据 → 生成裁剪／片段／引用 → 校验 → 发布发现与证据包。

复用现有 Finding 对象，但调整新版本的合成逻辑：同一来源、同一假设且空间或时间兼容的观察可以归入同一发现；每个原始观察和方向仍单独保留。不同帧、不同人物或不同文本上下文不能仅因名称相近而合并。区域重叠只帮助组织展示，不自动提高结论强度。候选选择规则和排序版本一并存储，避免每次打开页面临时换一张“最可疑”的图。

全局发现独立保留，只有存在合适的局部观察才创建局部发现。网页可先显示已有的完整证据包，补算状态单独提示；最终 PDF 必须冻结具体版本，不能把处理中或部分失败的证据描述为完整覆盖。

补算分为两类：既有测量生成裁剪或标注可以形成新的展示集合版本；新增检测或重评分若改变发现或结论，必须发布新的 analysis revision。新证据不能被追记为旧结论在当时已经拥有的依据。

## 发布校验与历史记录

在现有引用存在性检查之外，发布前还要校验：

1. 局部判断具有同一原件和分析版本的有效锚点；坐标、时间、页码、字符区间不越界。
2. 每个热力图、截图、片段确实来源于引用的 frame／page／PCM／文本，PTS 与秒数一致。
3. 检测观察引用成功的 detector／stage 运行和真实分析输入；原件、来源记录和人工意见按各自来源验证。跳过、失败和未分析不能被合并成阴性。
4. 测量的阈值、原生分辨率、上下文范围和校准状态完整；归因图不能升级为编辑定位。
5. 衍生图片能够由记录的源和渲染参数重建；截图不允许生成式修复、美化或补画疑点。
6. 每条解释的证据引用与所描述位置一致；相关展示不被重复计为独立支持。

历史 `schema_version=2.0` 和已签名结果不原地修改。能从旧记录可靠映射的证据可以生成新的、带来源说明的展示副本；缺少变换或坐标时标记缺失，需重分析才能补齐。不得通过给历史对象补默认字段而改变 canonical hash 后继续声称旧签名有效。

## 对外报告和模型信息保护

用户看到“局部编辑检查”“压缩一致性”“合成语音检查”等有意义的类别以及中性证据编号。隐藏模型名字不应删除测量内容、适用范围和误报说明；目前泛化为 “A detection check returned a score” 的句子需要改为结构化、可读的观察。

PDF 对每条发现输出同一证据包中的原件位置、原始局部内容、标注图或时间轨迹、观察和限制。公开 JSON 采用字段白名单；生成图片标签、PDF 嵌入附件、路径和元数据也要纳入投影检查。用户提供的原文或来源标记保持原样。

公开 ZIP 使用独立 schema，打包客户投影、可分享证据文件、PDF、文件清单及新签名。公开投影哈希与内部结果哈希分别说明；隐藏模型的公开包可以验证导出字节完整性，不能声称独立复现内部推理。旧签名文件不改写。详细基线沿用 [公开证据包设计](public-evidence-package-design.md)。签名验证与判断是否正确是两个独立问题。

## 验证数据与性能边界

工程正确性和检测准确性分别验收。小型固定样本用于映射、引用和导出的回归测试；独立、有足够真实对照的留出集用于阈值与准确性验证。训练、阈值开发与最终测试按来源、生成方式及内容去重，不能用同一批样本选阈值并报告效果。

| 媒体 | 必须包含的对照 | 主要指标 |
| --- | --- | --- |
| 图片 | 原始相机图、正常调色／裁剪／压缩、拼接、复制、局部生成及整图生成 | 真实图片被错误标区域的比例与误标面积、区域 IoU／像素 F1、边界误差、未检出比例 |
| 视频 | 原片、正常剪辑／配音／转码、换脸、局部生成、可变帧率 | 片段 precision／recall、时间 IoU、每分钟误报、边界误差、帧覆盖率 |
| 音频 | 真人语音、噪声／音乐／静音、电话压缩、整段合成、局部替换 | 真实语音误标时长、片段检出与边界误差、有效语音覆盖、未知生成方式表现 |
| 文本 | 人类原文、模板、翻译、语法润色、混合作者、改写、多语言及短邮件 | 每篇误标段落／字符比例、上下文检出、跨度重叠、各语言长度下的误报与拒判 |

误报目标及对应阈值在开发集上确定并冻结，报告测试样本量和置信区间。没有建立局部校准时，不发布局部概率或用一个汇总准确率掩盖不同媒体的差别。

本机运行沿用按需加载和受限内存队列，避免视觉、语音及文本大模型同时驻留；先用现有采样输出构建证据，再对候选区域／片段追加有预算的检查。记录峰值内存、耗时、取消／恢复、缓存命中、覆盖以及证据文件大小。缓存键包含源哈希、输入变换、检查版本和参数，不能只依赖文件名。实际性能目标待本机样例测量后设定。
