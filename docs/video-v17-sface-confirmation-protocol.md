# Fresh-source face-transition confirmation, version 17

This protocol freezes the successful v16 development method before fresh model
inference. It is a source-video/donor-disjoint confirmation, not proof of unseen
people or exclusion from upstream pretraining. The v16 development result and
its ten original requirements remain unchanged and public.

## Sources and boundaries

Use 30 new paired RTFS-10K source-video groups at the existing pinned revision
`bca865e675852666a426368b2f5614abf1c1926a`. For each group retain an original,
an InSwapper insertion, a UniFace insertion and an ordinary-edit control: 120
clips, 60 edited and 60 genuine/ordinary controls. Use the existing deterministic
source ordering and boundary-preparation helper, without selecting by model
response. Existing metadata exclude child-tagged entries; metadata are not an
independent age assessment. The dataset publisher declares CC BY-SA 4.0;
commercial model-weight permission does not establish all depicted-person rights.

The cumulative exclusion inventory reads only ignored independent-research
manifests, never customer uploads. Exclude every prior RTFS source-video ID and
donor filename (at least 132 groups and 264 donor files). Reject matching raw or
prepared media SHA-256 values against earlier research media and within this
acquisition. Save the exact plan before downloading. Preserve unsuccessful,
short or duplicate inputs and stop admission; do not replace them after observing
scores. Matching byte hashes cannot exclude all near-duplicates or shared people.

Unchanged helpers build 24 fps, 640 by 480 source-matched clips with known temporal
edit boundaries and verified original frames on both sides. Keep all ordinary
lighting/recompression/cut controls. No new generation model is run. Real clips,
frame imagery and all biometric feature vectors stay in private ignored storage.
Only source metadata, predicted ranges, statuses and aggregates may be published.

## Frozen methods and comparison

Keep the v16 native SFace model, alignment contract, input conventions, temporal
window enumeration, track rules, fallback and genuine-only point
**0.11243900750879454**, using strict greater-than for candidate eligibility.
This is an internal feature operating point, not a confidence, identity-match
point or customer screening threshold. Do not fit or select anything on these
fresh clips. Keep the current consecutive review point unchanged as well.

Unlike v16's held legacy receipts, rerun the existing commercial frame classifier,
face detection and tracking stages on all fresh clips. Then compute both current
consecutive and candidate appearance features on the same source/native clock,
triplets and tracks. Use the original v16 scorer without modifying its inference
or interval logic. Its historical-reference parity sidecar is explicitly removed:
a fresh clip has no historical reference, so do not report historical parity.
Retain the newly recomputed current windows and actual native alignment/input/
repeated feature/direct graph checks for every assessed candidate face.

The actual baseline uses the registry's admitted MIT DFDC ensemble, MIT YuNet
and Apache-2.0 DINOv2-small; candidate SFace weights have the previously reviewed
Apache-2.0 directory permission. Freeze source, input, assets, installed runtime,
configuration, tool versions and prior operating point before any fresh baseline
or candidate inference. Runtime source identity does not by itself establish an
independent implementation or training-data rights.

## Decision fixed before results

Retain the same 120-case, 30-group denominator as development and the same quality
requirements. A correct location means the first displayed range has temporal
intersection-over-union at least 0.30 with the known insertion. Require:

1. All 120 original cases and 30 groups accounted for, with no candidate failure.
2. Baseline and candidate original runs complete without resource/time guards.
3. All current checks recomputed on the fresh sources, and every applicable
   candidate native alignment/input/feature check passes.
4. More correct edit locations than the current method.
5. Total genuine/control review flags no more than current plus one, and ordinary
   edit flags separately no more than current plus one.
6. Mean edited-clip temporal overlap is not lower, and neither swap family loses
   correct localizations.

Unavailable cases stay in the denominator and preserve the current result. They
never become original-file verdicts. Also report source-group paired bootstrap
intervals with the v16 5,000-replicate seed 20261107; do not use those intervals to
retune the method. Report separate generator and control-family counts, retained
range evidence and sampled runtime/memory with sampling limitations.

Passing qualifies only for local integration and full ordinary-view/API/PDF/JSON/
frame-navigation/prepaid flow testing. It does not authorize an AI-probability
claim, overall-confidence weighting or court-use claim. Keep rollback available.
Failing means retain the current implementation and do not rescue the candidate
by changing these sources, boundaries, points or requirements.

## Operations and independent review

Run heavy studies sequentially, using isolated research state and the installed
application environment without new app dependencies. The parent guard stops at
6 GiB sampled process-tree RSS, less than 1.5 GiB available memory or disk, or
two hours. Preserve logs, exit status and guards; sampled RSS is a lower bound,
especially when transient subprocess exits prevent a complete sample. Acquisition
and preparation may occur before the inference freeze; no model output may.

Publish privacy-preserving source/range/aggregate resources and a separate numerical
review. Automated checks and another-machine CI are distinct from outside human
review, which remains zero. No outreach is authorized by this protocol. GCP remains
last, after detection and local customer-flow work.
