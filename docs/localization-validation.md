## What is measured

All comparisons use stored image pixels and reference-mask bytes, with no EXIF transpose on either side. Reference masks are grayscale values greater than 127. Authentic items have an all-zero reference mask. The benchmark does not replace the separate tests of EXIF-oriented UI coordinates.

Inference first produced a screening map, bilinearly resized to an aspect-correct grid with maximum side 1,024 and quantized to linear uint8. A fixed threshold of 0.5 is applied after the existing reliability mask. Nothing was tuned on this sample.

Four distinct mask selections are recorded:

1. `raw_threshold`: every grid cell at or above 0.5 and outside the unreliable area. “Raw” here still includes the reliability mask.
2. `area_retained_components`: the union of 8-connected components with at least `ceil(0.001 × grid_cells)` cells, minimum one cell. The actual component pixels are retained, including holes; enclosing rectangles are not filled.
3. `localiser_region_cap`: the component union after the localiser's maximum of ten regions, ranked by rounded mean score, rounded area share, then native bounding-box position. No sample had more than eight qualifying components, so this union is exactly recoverable from the old binary files and equals selection 2 here.
4. `per_map_display_cap`: the union after the current evidence view's per-map limit of two ranked components. This only measures the component cap. It does **not** reproduce packet eligibility checks, competing maps, or the total six-packet limit, and is not an end-to-end UI metric.

Binary files discard the scalar scores needed to rank components. Nine samples have more than two qualifying components: seven edited and two authentic. Their `per_map_display_cap` pixel metrics are explicitly unavailable. The available-subset mean uses only 93 edited images and must not be presented as a full-sample score. This audit does not choose arbitrary large components or rerun the model to conceal that missing history.

Each selected grid mask is projected to stored image dimensions by nearest-neighbour interpolation before comparison. IoU is intersection divided by union; pixel F1 is `2TP / (2TP + FP + FN)`. Reported means are unweighted means over edited images only. Pooled/micro IoU is separately named. Empty prediction and empty reference give IoU/F1 1, but authentic images do not inflate edited means. Undefined precision or recall is null. Missing metrics are counted and excluded, never replaced by zero or one.

## Reproduction and checks

From `backend/`, remeasure the frozen outputs without downloading data, loading a model, or touching existing files. Choose a new output path on every run; the script refuses overwrites.

```sh
.venv/bin/python scripts/localization_benchmark.py remeasure \
  --source-results data/localization-eval/mesorch-smoke-results.json \
  --output data/localization-eval/mesorch-smoke-metrics-recheck.json

.venv/bin/python -m pytest tests/test_localization_benchmark_metrics.py -q
.venv/bin/ruff check scripts/localization_benchmark.py tests/test_localization_benchmark_metrics.py
```

Thirteen tests passed in this audit. They cover component holes and minimum area; score-ranked caps; unavailable rankings from binary-only data; empty-mask conventions; frozen-result replay without writes; image/mask/manifest/prediction/label/count mismatches; and scalar/reliability reproduction of a threshold mask. Reproduction of all 200 existing samples also passed. These checks validate the measurement code, not the model's predictive accuracy.

A future fresh inference run uses a fresh directory, the same pinned selection, and writes scalar, reliability, and threshold PNGs plus their hashes. This audit did not execute these commands:

```sh
.venv/bin/python scripts/localization_benchmark.py prepare \
  --count 20 --root data/localization-eval-fresh
.venv/bin/python scripts/localization_benchmark.py evaluate \
  --device mps --root data/localization-eval-fresh
```

## Capability boundaries and local enablement

This is a small, ordered sample from one dataset and one screening setup. It does not cover all generators, unrelated camera distributions, edits after recompression or resizing, adversarial changes, or the deep tiled path. Source overlap and related images are not ruled out by byte deduplication. There is no representative sampling design, confidence interval for production use, threshold calibration, independent admission, or demonstrated distinction between benign edits and AI editing. A model response is an inspection clue; it is not provenance or causal proof. Reliability filtering can also exclude the edited area.

At inspection, the repository manifest keeps `loc.mesorch` disabled by default and the local development `.env` explicitly allows it. That local allowlist is an experimental override, not production admission. This task changed no runtime setting and restarted no API. Any local UI enabled by that override must retain the experimental/unvalidated interpretation; this note supplies no deployment approval or product accuracy claim.

The separate `backend/data/image-evidence-demo/manifest.json` identifies a known pasted composite and its unedited control, with source recipe and hashes. That fixture demonstrates evidence plumbing for a known compositing edit. It is not a generative-inpainting benchmark, is excluded from every denominator above, and must not be used to replace poor benchmark results or to pick successful examples for an accuracy claim.
